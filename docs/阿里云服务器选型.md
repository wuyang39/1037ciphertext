# 阿里云服务器选型

本文用于 A1-22 的 D1-D10 服务器阶段选型。结论基于 2026-10-09 的阿里云官方文档；规格库存、价格和可用区状态会变化，购买前仍须在控制台确认。

## 1. 最终结论

**主选：`ecs.g7t.2xlarge`，8 vCPU / 32 GiB / 16 GiB 加密内存。**

三节点正式联调和最终演示创建三台相同规格。它是本项目在 CPU、宿主内存、SGX 加密内存和成本之间最平衡的规格：

- 3PC RSS 和 Gramine-SGX/YACL/BRPC 有足够 CPU 余量。
- 32 GiB 宿主内存可容纳编译、Docker、Python、SPU 和调试工具。
- 16 GiB 加密内存对约 124M 参数的 GPT-2 small、`batch=1`、`context_window=16`、`max_new_tokens<=4` 的演示模型有足够余量。
- 5/10 Gbit/s 网络带宽基础/突发，适合三节点小规模 MPC 通信。
- g7t 明确支持 vSGX，且 Ice Lake 远程证明路径为 DCAP。

**D1 单机验证的最低建议：`ecs.g7t.xlarge`，4 vCPU / 16 GiB / 8 GiB 加密内存。**

该规格适合只运行 Hello Enclave、Quote 验证、最小 KAS 和加密文件验证。不要未经 profile 就将它作为三节点完整运行时的最终规格。

## 2. 规格对比

以下为官方规格表中与本项目相关的条目。`加密内存` 是阿里云规格表列出的规格能力，仍应在实例内通过实际驱动和运行时再次确认。

| 规格 | vCPU | 宿主内存 | 加密内存 | 网络基础/突发 | 适用结论 |
| --- | ---: | ---: | ---: | ---: | --- |
| `ecs.g7t.xlarge` | 4 | 16 GiB | 8 GiB | 3/10 Gbit/s | D1 单机最低建议 |
| `ecs.g7t.2xlarge` | 8 | 32 GiB | 16 GiB | 5/10 Gbit/s | 主选；D1-D10 |
| `ecs.g7t.3xlarge` | 12 | 48 GiB | 24 GiB | 8/10 Gbit/s | 预算允许时的稳健档 |
| `ecs.g7t.4xlarge` | 16 | 64 GiB | 32 GiB | 10/25 Gbit/s | 性能或内存压力被实测证明后升级 |
| `ecs.c7t.2xlarge` | 8 | 16 GiB | 8 GiB | 5/10 Gbit/s | 计算型低内存备选，宿主内存偏紧 |
| `ecs.c7t.4xlarge` | 16 | 32 GiB | 16 GiB | 10/25 Gbit/s | g7t 无库存时的首选替代 |
| `ecs.r7t.2xlarge` | 8 | 64 GiB | 32 GiB | 5/10 Gbit/s | 只有实测确认内存或 EPC 瓶颈时使用 |
| `ecs.g9it.2xlarge` | 8 | 32 GiB | 16 GiB | 12/25 Gbit/s | 更新代次，但当前为邀测，不作为比赛主选 |

不适合作为本项目 SGX 主选：

- `g6t`、`c6t`：当前官方规格页写的是可信启动和 vTPM，没有 SGX 加密内存规格；官方 SGX 文档列出的支持族是 `g7t`、`c7t`、`r7t`、`g9it`。
- `g9it`、`r9it`：当前标记为邀测，需要工单，不能把比赛日可用性建立在这些规格上。
- GPU 实例：RSS + SGX 主路径不依赖 GPU，使用 GPU 只会增加成本。

## 3. KAS/Audit 独立控制面

KAS 和 Audit 不需要 SGX，不要放在 P0/P1/P2 的自定义镜像中，也不要让 KAS 私钥进入 SGX 节点。

建议：

- 首选：`ecs.g7.xlarge`，4 vCPU / 16 GiB。
- 成本优先：`ecs.c7.xlarge`，4 vCPU / 8 GiB。
- 系统盘：100 GiB ESSD PL1。
- KAS 只接受节点私网地址访问；管理 SSH 仅允许本地固定公网 IP。

D1 阶段可暂时在本地运行最小 KAS。正式 D9 三域验收前必须拆分为独立控制面和独立审计域。

## 4. 地域与可用区

阿里云 SGX 远程证明服务和 PCCS 采用区域化部署。官方列出的中国内地候选地域包括：

- `cn-shanghai`（首选）
- `cn-hangzhou`
- `cn-beijing`
- `cn-zhangjiakou`
- `cn-qingdao`
- `cn-shenzhen`
- `cn-heyuan`
- `cn-guangzhou`
- `cn-chengdu`

选择顺序：

1. 先在 `cn-shanghai` 购买页确认 `ecs.g7t.2xlarge` 有货。
2. 无货时依次检查 `cn-hangzhou`、`cn-beijing`、`cn-zhangjiakou`。
3. 三台 SGX 节点必须同地域、同 VPC，优先同可用区。
4. 不要为了有货把三节点拆到不同地域；跨地域会把 MPC 通信和证明链路变成额外风险。
5. 最终选择以购买页显示的可用区和实时库存为准，不能只依赖公开文档。

## 5. 购买参数

每个 SGX 节点的建议配置：

| 项目 | 建议 |
| --- | --- |
| 计费方式 | 按量付费 |
| 实例规格 | `ecs.g7t.2xlarge` |
| 镜像 | Ubuntu 22.04 UEFI 或阿里云 SGX 专用镜像 |
| 可信系统 | 勾选；让控制台注入并执行 vSGX 安装脚本 |
| 实例 RAM 角色 | `AliyunECSInstanceForYundunSysTrustRole` 或具有同等可信服务权限的角色 |
| 系统盘 | 100 GiB ESSD PL1 |
| VPC | 独立测试 VPC，三节点同 VPC |
| 公网 | 仅在需要安装依赖时临时分配；正式联调用私网 |
| 安全组 | 节点间端口仅私网；KAS 仅节点私网；SSH 仅本地 IP |
| 登录方式 | SSH 密钥，不使用密码 |
| 自动释放 | 验收完成后手动确认并释放；不要依赖节省停机 |

如果账号还没有 SSH 密钥，应先在目标地域创建密钥对；不要为了省一步长期使用“创建后设置”加控制台重置密码的方式。短期 D1 验收可以临时使用“创建后设置”，但必须在实例创建后立即配置 `ecs-user` 密钥或强密码，并把安全组 SSH 来源限制为本机公网 IP。

如果使用 SGX Sealing，不要使用“节省停机”后再次拉起作为长期策略。官方说明实例变更、停机再启动或宿主迁移可能导致硬件绑定数据无法解密。应保存自定义镜像和数据，然后释放实例。

## 6. 购买后的 D1 自检

实例启动后先执行：

```bash
cpuid -1 -l 0x7 | grep SGX
ls -l /dev/sgx_enclave /dev/sgx_provision
systemctl status aesmd
cat /etc/sgx_default_qcnl.conf
```

预期结果：

- `SGX: Software Guard Extensions supported = true`
- `SGX_LC: SGX launch config supported = true`
- `/dev/sgx_enclave` 和 `/dev/sgx_provision` 存在
- `aesmd` 正常运行
- `PCCS_URL` 指向实例所在地域的阿里云 PCCS

随后必须完成：

1. 编译并运行 SGX `SampleEnclave`。
2. 运行 `QuoteGenerationSample` 生成真实 Quote。
3. 运行 `QuoteVerificationSample` 验证 Quote。
4. 运行 Gramine-SGX 最小程序。
5. 生成非 debug Quote，并由 KAS 验证 `MRENCLAVE`、`DEBUG=0` 和 nonce。

未通过以上 D1 检查时，不进入 D3-D10 的真实 SGX 集成。

## 7. 成本控制顺序

1. D1 只购买一台 `ecs.g7t.xlarge`，数小时内完成环境验证并保存自定义镜像。
2. 本地完成 D2-D8 的可测试部分，不长期保留 SGX 实例。
3. 三节点联调购买三台 `ecs.g7t.2xlarge`，同地域同 VPC，短时运行。
4. 只有在 profile 证明 CPU、宿主内存或 EPC 不足时，才升级到 `g7t.4xlarge` 或使用 `r7t`。
5. 结束后保存日志、Quote、镜像 ID、模型哈希和 trace，释放 ECS，检查云盘、EIP、快照和镜像是否继续计费。
